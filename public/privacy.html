Guest mode and an optional account

You can shop with no account. The list on this device stays in local storage until you delete it or sign in. Sign-in is optional and is hidden until it is turned on. When it is on, you can use Sign in with Apple, Google, or an email link. Grocery Gitter does not set a password of its own. An email address is stored only if you use the email link, or if Apple or Google sends a verified address. Apple may hide your address behind a private relay. Signing in moves this device’s list, price alerts, shared lists you created, and the Kroger link onto that account so another signed-in device can use them. If you share a list, you can still type an optional display name. That name is not an account.

You can still delete the data this device stored. Open Settings and choose Delete my data, then type DELETE. If you are signed in, that also deletes the account. That is described below.

Saved on this device

A few things stay in local storage on the phone, tablet, or browser. They are not a Grocery Gitter account:

  • Your ZIP code.
  • My list, until you share it: the items you checked, including the name, brand, size, and quantity, plus any price-alert setting on those items.
  • Whether you allow substitutes in the trip plan.
  • Whether you turned on price alerts for the list.
  • Your theme: light, dark, or match this device.
  • A random id this browser creates for price alerts. It is not a hardware id and not an advertising id.
  • The optional display name, if you typed one.
  • If you shared a list, the share link and the owner secret for that list.

Clearing site data for Grocery Gitter, or deleting the app, removes them from this device. It does not remove a shared list or a price watch already saved on the server. Delete my data does both.

What is sent when you shop

Browsing, search, and Plan the trip send a request to Grocery Gitter’s server over HTTPS. That request can include the ZIP code, the words you searched, and — when you plan a trip — each item’s name, brand, quantity, catalog id, and UPC when we have one, plus whether you allowed substitutes.

The server uses that request to look up prices and return a trip. That request is not stored as your shopping list. A list is stored on the server when you share it. A price watch is stored when you turn alerts on, or when you watch one item on its own. Both are described below.

The 5-digit ZIP is saved in our database, without your name or a device id. The record is a hit count, the last time that ZIP was used, and sometimes the Kroger store id we resolved for it. The catalog job uses a short list of recent shopper ZIPs (currently up to 12, plus a few cities we seed ourselves) so prices can be refreshed near places people actually shop. Email [CONTACT EMAIL] with the ZIP if you want that record removed.

Shelf answers may be cached for a few hours, keyed by department, search words, and ZIP. That cache is product data, not a profile of you.

The ZIP is something you type. Grocery Gitter does not request GPS or other device location permission. The same ZIP can also be saved on a price watch, as described under price alerts.

Shared lists

My list starts on this device. When you tap Share list, Grocery Gitter stores a copy on the server so someone with the link can open it.

That copy includes:

  • Each item: the name, and when we have them the brand, size, quantity, catalog id, and whether it is checked. An item someone removes is kept as a deletion marker so the other phones can catch up. A list holds up to 100 items, and up to 100 of those markers.
  • An optional display name, up to 40 characters, on an item you add or check, if you typed one under “Your name on this list.” If you leave that blank, no name is stored.
  • A title. If you do not set one, it is “Shopping list.”
  • Whether the link is editable or view-only.
  • Timestamps for the list and for each item.
  • SHA-256 hashes of the share secret and of the owner secret. The raw secrets are not stored. They stay in this browser and in the link you send. When a link is replaced, the server also keeps up to 10 earlier share hashes so the old link can be recognized and refused.

Anyone with the current link can read the list. They can edit it unless you made the link view-only. The owner secret is what lets you revoke the link or share a new one.

Revoke link marks the list revoked and leaves the items, display names, and timestamps in place. Someone who opens the old link sees “This link was turned off.” You can still open the list from the browser that holds the owner secret, and you can share a new link. Sharing a new link turns the old address off the same way. Revoking or replacing a link does not delete the list.

The database does not expire a shared list. Revoke link leaves the stored list in place. Delete my data removes a list you created on this device and turns the link off for everyone you sent it to. Email [CONTACT EMAIL] if that control does not work.

Kroger sign-in

Add to Kroger cart is optional. When it is turned on and you use it, you sign in on Kroger’s own site. On the iOS and Android apps that page opens in the system browser. We never see your Kroger password.

Kroger returns a short authorization code. We exchange it for an access token and, when Kroger sends one, a refresh token. Those tokens are encrypted with AES-256-GCM and kept in an HttpOnly cookie named kroger_shopper (SameSite=Lax, and Secure on the production site). The cookie is not written to our database. It lasts about 7 days when a refresh token is present, and about 40 minutes otherwise. We use the token only to ask Kroger to add items — UPC, quantity, and pickup or delivery — to your Kroger cart.

While you approve that cart, the item UPCs, quantities, names, and store location travel in a signed link that expires after 15 minutes. A copy may sit in the memory of the server that started the login, for that same window. It is not a saved list.

Retailer handoffs

Opening a store leaves Grocery Gitter. On the phone apps those links open in the system browser. The retailer’s own privacy policy applies once you are on their site.

  • Kroger. A search link, or the cart write above. The nearby-store lookup sends your ZIP to Kroger’s locations API. Product search sends product words or a UPC.
  • Walmart. A search link or an add-to-cart link. When Walmart keys are set, product search and the nearest-store name and address go through Walmart’s affiliate API. We do not sign you into Walmart. Prices are Walmart’s website catalog, not a private store account.
  • Target. A search on target.com. If a licensed Target feed is configured on the server, the search and ZIP are sent to that feed. There is no Target login in this app.
  • Weekly ads. When that option is on, Aldi and other mapped banners send the ZIP and a search term to Flipp. There is no retailer login.
  • Instacart. Only if you tap that button and the integration is turned on. We then send Instacart the item names, quantities, and any brand, size, unit, or UPC we have, plus the ZIP, and open the shopping-list link Instacart returns.

Price alerts

Price alerts are optional. They start when you check “Alert me when prices on this list drop,” or when you watch one item on its own. This browser then sends a watch to the server.

A watch stores:

  • The random id created on this device, the list id, and the list name.
  • The 5-digit ZIP, when you have entered one.
  • Each item that has a saved price: the product id, name, brand, whether that item is watched, the baseline price and the store from when you saved it, and a target price if you set one.
  • Whether the list-level alert checkbox is on.

Turning that checkbox off saves the watch as disabled. The watch stays, including the items and the ZIP last sent with it. An item you set to watch on its own can still be checked after the list checkbox is off. Switching to a different list disables the previous watch and clears that watch’s items; the watch row itself stays. None of these steps deletes past alerts.

When a watched price drops, the server stores an alert record: the item, the store, the old and new price, the savings, the baseline price, any target price, and whether you have opened it. Opening the price-alerts panel marks those alerts seen. It does not delete them. The panel loads the latest 40. The app does not expire alert history on a timer. Delete my data removes the watches and alert records stored for this device.

Browser notifications

Notifications are a separate choice, and only when the server is configured with VAPID keys. If you tap “Notify this browser” and allow notifications, we store the Web Push subscription: the endpoint, and the p256dh and auth keys the browser provides, together with the same random device id. We use that subscription only to send a price-drop notification.

Turning the alert checkbox off does not remove the subscription. Delete my data does. It deletes the subscription stored for this device and unsubscribes this browser. The server also deletes a subscription when the browser’s push service reports that it is gone. The iOS and Android shells do not register a phone push token. Nothing in the app deletes a subscription on a timer.

Analytics and crash reporting

Grocery Gitter does not include a third-party analytics or advertising SDK. There is no advertising identifier. The shopper screen does not call a separate nutrition-catalog search.

Crash and error reporting is optional. It stays off until SENTRY_DSN is set. When that variable is unset, the website, the iOS and Android apps, and the server do not start Sentry and do not send crash reports. When it is set, those same places send a report to Sentry so a crash can be fixed. Sentry is not used for advertising or for a usage profile.

A report can include the error message, a stack trace, the release (the git commit that was built), the operating system or browser, and the page or API path. It does not include your email address, your name, your grocery list, a Kroger access or refresh token, the kroger_shopper cookie, other cookies, or Authorization headers. Reports are not tied to the random price-alert id and not tied to an account. Signing in does not put the account id on a crash report.

Sentry stores those reports. They are not rows in the Grocery Gitter database. Delete my data does not remove them, and it does not turn crash reporting off. Clearing site data or deleting the app stops reports from this device until Grocery Gitter is opened again. Because a report is not linked to you, email [CONTACT EMAIL] with the approximate time and whether you were on the website, an iPhone, or Android. We will delete matching crash reports when we can tell which ones they are. We cannot promise to find a report that has no identifier.

The server writes operational logs, for example when a store lookup fails or the catalog job is running. The host that runs the site may keep ordinary request logs: IP address, time, and the path that was requested. Those logs are for operating the service. They are separate from Sentry.

Delete my data

Open Settings. It is at the top of the screen, at the bottom of My list, and in the page footer. Choose Delete my data and type DELETE. With no account, the request is for this device: the random id stored here, the owner secret if you created a shared list on this device, and the Kroger cookie if this browser has one. If you are signed in, the same request also deletes the Grocery Gitter account, including the saved list and the other devices on it.

That removes:

  • The list, ZIP, theme, display name, and other Grocery Gitter values saved on this device.
  • Price watches, alert records, and Web Push subscriptions stored for this device. This browser is unsubscribed from notifications.
  • Shared lists you created on this device. The link stops working, including for people you sent it to. Price watches saved for that link are removed, because those rows store the link and the item names. Someone else’s own list is left alone.
  • The Kroger access token and refresh token. On the website the cookie is cleared in this browser. On the iOS and Android apps, Grocery Gitter also opens a page in the system browser so the sign-in stored there is revoked and dropped. That page is the hosted /api/kroger/logout address. The Kroger login itself happens in the system browser, so the app WebView does not hold that cookie.
  • The Grocery Gitter account, when you are signed in. That includes the saved list, the Apple, Google, or email sign-in, and shared lists linked to the account.

Doing it twice is safe. The second time there is nothing left to remove.

ZIP totals and the words used to decide which products to refresh are not stored with your device id. They are counts shared by everyone who typed the same ZIP or the same search. Delete my data does not erase those counts. Email [CONTACT EMAIL] with the ZIP or the search words if you want a count reviewed. Host request logs, when the host keeps them, are not deleted by the button. Crash reports are not tied to an account, so Delete my data does not remove them either.

After the data is removed, the app starts over as if this device had not been used.
